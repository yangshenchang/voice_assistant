# cpolar 外网联调清单

> 目的：**在花那 ¥99 之前**，先用免费版把"手机 4G → 公网 → 家里 → 语音助手"这条路跑通，
> 并**量出真实延迟**。延迟能不能接受，决定后面要不要付费、要不要换方案。

---

## ✅ 结论（2026-09-29 实测已跑通）

| 指标 | 实测值 | 判断 |
|---|---|---|
| 手机（4G）网络 RTT | **96 ms** | ✅ 只比局域网多约 95 ms，几乎无感 |
| 丢帧 | **0** | ✅ 免费版 1 Mbps 对语音完全够（需求仅约 650 kbps） |
| 连续通话 | 01:36 未断 | ✅ 长连接稳定 |
| 隧道额外往返（长连接） | **76 ms** | ✅ 单程约 38 ms |

**最终判定：这条路可用，而且免费版就够。**
`¥99` 的唯一理由是"URL 24 小时变一次"——与延迟无关。

### ⚠️ 一个把我带偏过的测量陷阱（务必记住）

我最初用 **HTTP 短连接**（`curl` 式）测隧道，得到 **480~530 ms**，据此判断"延迟偏大、
可能是限速"。**这个结论是错的**，因为：

| 测量对象 | 结果 |
|---|---|
| HTTP 短连接（每次新建） | 480~530 ms |
| **WebSocket 长连接（实际链路）** | **76 ms** |

差 **8 倍**。根因：隧道对"新建连接/短请求"的开销很大（疑似 1 Mbps 额度下的握手排队），
而**连接一旦建立就很快**。我们的语音链路正是一条持久 WSS ——
**拿短连接去评估长连接链路，测的是错的对象**。

> 正确做法：要评估语音链路的时延，就测 **WebSocket 的 ping/pong RTT**
> （客户端页面上那个「网络 RTT」就是它），或者直接用真机跑一轮。
> 相关工具：`tools/probe_external.py`（只读诊断，含"短连接延迟"参考值）。

## 零、先明确这次要回答的问题

| 问题 | 怎么回答 |
|---|---|
| 手机在 4G 下能不能连上？ | 打开 cpolar 给的 https 地址，页面能出现 |
| **能不能通话？** | 接通 → 说话 → 听到回复 |
| **延迟能不能接受？** | 页面上的「网络 RTT」与「本轮」两个数字 |
| 带宽够不够？ | 语音时有没有断续、丢帧计数是否增长 |

**判据**（实测后的修订版：长连接下 RTT 应远小于下表的"可接受"线）：

| 指标 | 可接受 | 勉强 | 不可接受 |
|---|---|---|---|
| 网络 RTT（长连接 ping/pong） | < 150 ms | 150–300 ms | > 300 ms |
| 本轮首包时延 | < 3 s | 3–4 s | > 4 s |
| 丢帧计数 | 0 或不增长 | 偶尔 +1 | 持续增长 |

> 基线参考：局域网 RTT ≈ 1 ms、首包 ≈ 1.5 s；经 cpolar 实测 RTT **96 ms**。

## 一、PC 侧：起服务（**关掉 TLS**）

```powershell
python run.py --serve-remote --no-local-mic --no-auth --port 8801 --no-tls
```

| 参数 | 为什么 |
|---|---|
| `--no-tls` | **关键**。cpolar 的 HTTP 隧道会在它自己的边缘做 TLS，我们这边再用 TLS 就是套两层，且自签证书会让手机报警。关掉后手机看到的是 cpolar 的**公信证书**，不报警 |
| `--no-local-mic` | 只服务手机（也省掉 8 秒 KWS 加载） |
| `--no-auth` | 先跑通，**连通后立刻改成 `--token <强口令>`** |
| 不加 `--wait-connection` | 别让它卡在等连接，我们直接用 cpolar 探 |

启动后应看到：

```
🔇 按参数要求不开本机麦克风（只服务远端）
📱 手机端（同一局域网内打开）:
     http://192.168.0.8:8801/          ← 注意是 http，因为关了 TLS
```

先在本机浏览器打开这个 http 地址确认页面正常，**再往下走**。

## 二、cpolar 侧：建 HTTP 隧道

```powershell
cpolar authtoken <你的token>      # 只需一次
cpolar http 8801                  # 把本地 8801 暴露出去
```

输出里会有一行 Forwarding，形如：

```
Forwarding   https://xxxxxxxx.r30.cpolar.top -> http://localhost:8801
```

**要记的就是那个 `https://xxxxxxxx.r30.cpolar.top`。**

> ⚠️ **别动你现有的 cpolar 配置**：你 `~/.dsh/settings.yaml` 里已有一条指向
> `12.tcp.cpolar.top:12781` 的 provider（在用的东西）。这里是**新建一条 http 隧道**，互不影响。

自检（在 PC 上先验一遍，确认隧道把请求送到了本机服务）：

```powershell
# 期望：这是你语音服务的 /health JSON（含 "tls": false）
curl.exe https://xxxxxxxx.r30.cpolar.top/health
```

> 若 `curl` 走了本机代理导致失败，加 `--noproxy "*"`。

## 三、手机侧：4G 实测

1. **关掉 WiFi**（这一步不能省——不关 WiFi 走的是局域网，测不出公网延迟）
2. 打开 `https://xxxxxxxx.r30.cpolar.top`
3. 页面应正常出现（**不应有证书警告**，因为用的是 cpolar 的公信证书）
4. 点「接通」→ 允许麦克风 → 直接说话
5. 读页面上的数字：**网络 RTT**、**本轮**（首包时延）、**丢帧**

## 四、按现象定位（这是本清单的主要价值）

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 手机打不开页面（一直转圈/超时） | cpolar 隧道没起、或域名抄错 | 看 cpolar 是否在运行；用 `curl --noproxy "*"` 自检 |
| 页面能打开，但**点接通后立刻"已断开"** | WebSocket 升级被隧道/代理拦了 | 看 PC 端服务日志有没有 `远端已连接`；没有就是没转发过来 |
| 页面能开、也能连，但**按钮一直"处理中…"** | 服务端那轮出错了 | 看 PC 端日志：应有 `识别: …`。若没有，是音频没上来 |
| 能连、有音频上下行，但**声音断续** | 带宽不够或抖动 | 看丢帧计数是否增长 → 增长才是带宽/抖动问题（实测免费版 1 Mbps **够用，丢帧 0**） |
| 手机提示**不安全/证书错误** | 你忘了 `--no-tls` | 服务端还带着自签 TLS，关掉它 |
| 手机**拿不到麦克风** | 页面不是 https（比如你用了 http 地址） | 必须用 cpolar 给的 **https** 地址 |
| 提示 **`no_speech`（没听清）** | 多种来源，需看服务端日志区分 | 日志有 `Segment: x.xxs` 说明切句成功；有"片段过短…跳过云端 STT"说明 < 0.35 s 被主动跳过（省一次注定失败的请求）；有 `No speech recognized` 才是真识别为空。**都没有 = VAD 没切出句子** |

**PC 端日志里你最该盯的两行**：

```
远端已连接 phone:xxxx peer=<真实来源IP>(via proxy)     ← 这一行出现 = 隧道通了
识别: <你说的话>                                        ← 这一行出现 = 音频真的上来了
```

`(via proxy)` 标识来自 `X-Forwarded-For`：走隧道时 TCP 来自本机、`remote_address` 恒为
`127.0.0.1`，不看这个头就分不出"谁连上来了"；**没有这个标识反而说明请求不是经代理来的**。

## 五、公网部署安全清单（**跑通后必做**）

公网入口一旦存在，安全项就不该靠记忆。逐条确认：

| # | 项 | 做法 |
|---|---|---|
| 1 | **必须开语音口令** | 去掉 `--no-auth`，显式给一个强口令：`--token <你定的口令>`。服务端在 `hello` 帧校验，不符即 `error[unauthorized]` + `bye` |
| 2 | **别把 RDP（3389）挂到隧道** | 实测发现曾有 `remoteDesktop: tcp 3389` 隧道。**公网 RDP = 勒索软件最经典入口**，不是"和语音服务同等级"的风险 |
| 3 | 检查其它 `enable` 的隧道 | 配置里每条 `start_type: enable` 都是对外暴露面，逐条确认是否真需要 |
| 4 | 别暴露 `3080`（本机 DSH Web GUI） | 那里面是握着全权限 shell 的 agent，等同于把 shell 挂公网 |
| 5 | 口令来源 | ⚠️ `--token xxx` 会明文出现在命令行（`Get-Process` 可见）。家里环境风险低，但更干净的方式是从环境变量或文件读（**待实现**） |
| 6 | 失败限流 | 目前没有。公网入口建议加"同 IP 连续错口令即临时封"（**待实现**） |

## 六、要不要付费（实测后的结论）

| 理由 | 是否成立 |
|---|---|
| ❌ "延迟太高，要提带宽" | **不成立**。实测 RTT 96 ms、丢帧 0 —— 延迟与带宽都不是瓶颈 |
| ✅ "URL 24 小时变一次，每天要重新看一眼地址" | **唯一成立的理由**。嫌烦就上 **¥99 基础版**（保留二级子域名 = 固定网址）；不嫌烦 **¥0 就够** |

> 换节点也别折腾：实测 r12（阿里云北京）、r9（阿里云香港）、tcp vip、主站 .com
> 四个控制节点，TCP 握手 25~52 ms，**换节点对长连接体验没有实质影响**。
